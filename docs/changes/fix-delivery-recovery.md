# Recover followup delivery claims

Direct followup delivery now records a durable, owned in-progress claim without setting `delivered` or `acked`. A successful `agent.prompt` (including the existing prompt-landed timeout case) finalizes the claim; a prompt failure releases only that attempt's token, and consuming the message through `pack-leader inbox` also finalizes it. `sync` and `inbox` can reclaim abandoned claims: a dead sender on the same host is recoverable immediately, while remote or otherwise ambiguous owners are bounded by a five-minute lease. Concurrent delivery remains fenced while a claim is live, and direct prompts include the stable message ID so a worker can recognize a retry.

This is intentionally at-least-once under an ambiguous backend outcome: if herdr applied a prompt but the sender died before it could finalize the claim, the message may be prompted again after recovery. A prompt that remains unresolved past the five-minute lease can also be retried; the stable ID makes either duplicate identifiable. Existing state written by an older version that already stored `delivered: true` and `acked: true` without a claim is indistinguishable from completed delivery and cannot be automatically recovered; all new claims retain their pending state until completion.
