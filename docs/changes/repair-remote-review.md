# Remote callback authority and delivery ambiguity

Remote callback relays now bind explicit `--run` and `--worker` flags to the callback context, including `--flag=value` forms and repeats. Before re-executing any callback verb, the leader reads the state file selected by the callback's leader state directory and verifies that the effective task/dispatch pair is the current pair for that same registered worker. This rejects stale pane context, cross-worker/cross-run overrides, and stale callbacks for verbs such as `inbox`, `send`, and `ask --id`; explicit current task/dispatch flags remain valid after remote redispatch. This is an argv/context authority check, not cryptographic per-worker isolation: a peer able to use the configured SSH account can author callback context, and that account remains trusted.

Remote prompt retries now classify SSH transport and protocol failures as ambiguous. Receipt reconciliation observes the original target pane on its snapshotted execution host: a changed state sequence or `working` state is only probable evidence of receipt; a successful observation matching the captured baseline permits retry; an unavailable or invalid observation remains unknown and never authorizes automatic replay. A baseline that could not be captured cannot establish nonreceipt.

When a remote followup's receipt remains unknown, its stable message ID and recipient snapshot are persisted as `delivery_unknown`. Sync and later senders reconcile that evidence before retrying, including after process restart or claim expiry; unchanged evidence may eventually permit retry, while continued uncertainty leaves the followup unacked. Worker inbox consumption and release/drop still resolve the queued message. Expired remote in-progress claims also retain the target, worker incarnation, host snapshot, and baseline needed to reconcile before retry. Local delivery keeps its existing at-least-once crash recovery behavior.

Remote worker starts that cannot determine prompt receipt return an actionable warning while leaving the dispatch authoritative; they do not silently roll it back or auto-resend. Herdr provides no delivery receipt or idempotency key, and sequence/status evidence is heuristic: unrelated state changes, delayed observations, a host identity change, or a crash before uncertainty can be observed can still leave ambiguity. These changes reduce blind duplicates but do not provide exactly-once delivery.
