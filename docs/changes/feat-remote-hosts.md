# Remote execution hosts

Remote workers can now be placed with `pack-leader worker start NAME --host HOST --cwd /remote/absolute/path --spec ...` (or `--task ...`). Add trusted SSH profiles with `host add/list/show/remove`; profiles store SSH targets and remote workspace/socket/executable coordinates, never credentials.

The leader keeps the only authoritative state and dispatch history. Each remote worker/dispatch stores a profile snapshot, and all remote herdr operations (start, prompt/redispatch/resend, queued delivery, observation, read/archive, focus, stop and owned-resource release) route through a bounded SSH stdio RPC helper and the host's Unix socket. If a remote socket is omitted, the helper uses the normal `herdrSocketPath()` resolution on that host. Worker callbacks return over reciprocal SSH through a strict `done/ask/note/heartbeat/send/inbox` relay, preserving stdout, errors, exit status and blocking asks while the normal worker authority checks fence stale dispatches. Callback subprocesses receive the leader's resolved state directory/socket before module initialization, and relative report paths resolve against the remote worker's cwd.

Remote workers require an already-existing remote workspace and absolute POSIX cwd. Remote worktree creation/removal, local setup hooks and adoption are rejected/unsupported; no local git operation runs on a remote path. SSH is non-interactive (`BatchMode`), keeps host-key verification strict, and remote liveness failures preserve worker/task state instead of marking it exited. A real remote end-to-end run is unavailable until a host with reciprocal SSH access is configured.

Remote release shares the run-start fence with remote redispatch and resend across SSH preflight, archive, close and state removal; atomic state locks are not held over network I/O. A failed SSH preflight leaves worker/task registration intact. Waiting checks do not write state on state-file wakes, and remote liveness polling remains on a wall-clock 1.5-second cadence. SSH timeout or output overflow triggers TERM, bounded KILL and local pipe destruction so descendants holding inherited descriptors cannot keep the CLI alive. This bounds the local transport only; it is not a process sandbox, and the remote command may already have been accepted. CLI error envelopes expose codes only from the known HerdrError, RemoteError and HostProfileError classes.

Regression tests were added for fake delayed archive/close races, SSH failure preservation, escaped pipe holders, and safe error-code serialization, alongside routing/callback/host isolation coverage. **Tests, typecheck, lint and runtime probes were not run by user request; only static review and `git diff --check` are permitted in this implementation phase.**
